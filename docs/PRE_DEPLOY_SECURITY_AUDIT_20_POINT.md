# 20-Point Pre-Deploy Security Audit — Agency OS

**Audit date:** 2026-11-25
**Scope:** `agency-native-agency-os` current reconciled PR branch, backend, frontend source, migrations, Docker Compose and declared dependencies.
**Disposition:** **NOT APPROVED FOR PRODUCTION**. This is a source/configuration review plus automated dependency and backend-test evidence, not a penetration test, production-environment review or compliance assessment.

## Executive result

- **Verified / not applicable:** 5 controls (SQL injection source review, XSS sink review, no file-upload surface, explicit production source-map setting, dependency audit).
- **Partial:** 9 controls (CSRF applicability, SSRF, BOLA, server-side RBAC, JWT controls, API-key handling, CORS, webhook coverage and logging hygiene).
- **Failed / not implemented:** 6 controls (general rate limiting, production password authentication, MFA, PostgreSQL RLS, browser token storage and safe default-credential enforcement).
- **Dependency audit:** npm audit reports 0 vulnerabilities after the frontend dependency patch; pip-audit reports no vulnerabilities in runtime and development requirements after moving pytest to development requirements and upgrading it.

The checklist has 20 rows below; statuses are deliberately conservative. A control marked verified only describes the current code surface, not a guarantee against all attacks.

## Detailed 20 controls

| # | Control | Status | Severity | Evidence / exact finding | Required patch or remaining verification |
|---:|---|---|---|---|---|
| 01 | SQL injection | **Verified (source review)** | Critical | SQLAlchemy ORM queries are used throughout. The only application `text()` call found outside migrations is a fixed literal `SELECT 1` in `app/main.py:108-116` and `app/tool_registry.py:167-178`. AST review found no f-string or concatenated SQL passed to `text()`. | Keep all future SQL parameterized. Add static SQLi scanning to CI and review future raw SQL changes. |
| 02 | XSS | **Verified (source review, limited)** | Critical | No `dangerouslySetInnerHTML`, `.innerHTML`, `document.write` or `eval()` sinks were found in authored frontend `.ts/.tsx` files. React renders user-controlled values through normal escaped JSX. | Preserve escaped rendering. If rich HTML/Markdown is introduced, sanitize with a maintained sanitizer and add browser tests with hostile payloads. |
| 03 | CSRF | **Partial / bearer-only design** | High | API authentication currently uses the `Authorization: Bearer` header in `frontend/lib/api.ts:3-13`; the backend reads the header in `app/auth.py:35-42`. No auth cookie is issued today, so classic ambient-cookie CSRF is not the current primary risk. | Before switching to cookies, implement synchronizer/double-submit CSRF protection, `Secure; HttpOnly; SameSite=Lax/Strict`, Origin checks and tests. Do not solve CSRF by reverting to localStorage. |
| 04 | File upload validation | **Not applicable (no upload surface found)** | High | No FastAPI `UploadFile`/`File()` routes or frontend upload flow were found in authored source. | Keep upload routes absent until needed. Any future upload must enforce body/size limits, MIME + magic-byte validation, safe names, malware/content scanning as appropriate, quarantine and workspace-scoped storage. |
| 05 | SSRF prevention | **Partial** | High | User-supplied research URLs are stored as references, not fetched, in `app/domain_routes.py:289-298`. The Claude adapter makes outbound requests to configured `anthropic_api_base_url` in `app/integrations/managed_agents.py:46-61`; the tool registry validates public HTTPS URL syntax/IP literals in `app/tool_registry.py:42-69`, but does not perform DNS resolution or enforce network egress. | Keep user-supplied URLs non-fetching. Validate provider base URL against a fixed HTTPS host allowlist at startup; block private/loopback/link-local/metadata destinations at egress and after DNS resolution; disable redirects or revalidate every redirect; test DNS rebinding and IPv4/IPv6 cases. |
| 06 | BOLA / IDOR | **Partial — application scoping exists; DB isolation missing** | Critical | Organization membership and workspace checks exist in `app/auth.py:44-49`, `app/domain_routes.py:25-44`, `app/main.py:125-134` and other route modules. Run the PostgreSQL cross-tenant test suite; enforce database RLS as a second boundary. |
| 07 | Rate limiting | **Failed / incomplete** | High | `app/outreach/routes.py:120-137` enforces sender-level hourly/daily caps. No general IP/user limiter, Redis-backed login/API limiter or expensive-endpoint throttle was found. | Add distributed Redis-backed limits for authentication, token issuance, machine sessions, expensive research/evaluation endpoints and public website intake. Include trusted-proxy handling, `429`, `Retry-After`, bounded keys and abuse tests. |
| 08 | Secure password hashing | **Not implemented — no password login found** | Critical | No password field/hash, Argon2id/bcrypt dependency or password authentication endpoint was found. Current user auth accepts bearer JWTs; development token issuance is in `app/main.py:88-105`. | Do not add ad-hoc password storage. Choose an identity provider or implement a complete production auth lifecycle with Argon2id (or bcrypt cost >=12), reset/verification flows, throttling and tests. Until then, production login is not ready. |
| 09 | MFA | **Not implemented / external control unverified** | Medium | No TOTP, WebAuthn, MFA challenge or enforcement was found in application code. | Require MFA through the selected identity provider for founder/admin identities and sensitive actions; record verified MFA assurance in the server-side session and test enforcement. |
| 10 | Server-side permissions | **Partial** | Critical | Backend role and explicit Founder Authority checks exist in `app/auth.py:44-53,64-89`; route modules use them. Workforce tool execution now also checks exact capability grants. | Complete a route-by-route permission matrix and negative tests for every privileged action. Verify founder-only approval consumption and protected action are atomic. UI hiding is not authorization. |
| 11 | PostgreSQL RLS | **Failed / absent** | Critical | No `ENABLE ROW LEVEL SECURITY`, `CREATE POLICY`, `FORCE ROW LEVEL SECURITY` or `pg_policies` policy migration was found. | Add tenant/workspace RLS policies, use a non-owner/non-BYPASSRLS application DB role, set transaction-local tenant context safely, force RLS where appropriate and test owner bypass, missing context, pooled-connection leakage and cross-tenant access on PostgreSQL 16. |
| 12 | JWT secret security | **Partial — release blocker** | Critical | `app/config.py:8-13` defaults to `unsafe-development-secret-change-me`; `app/auth.py:17-20` only checks production secret length >=32 when decoding. No `kid`/key ring/rotation mechanism was found. | Fail application startup in production unless dev auth is disabled and a cryptographically random >=256-bit secret/key is supplied. Use a key ID and overlapping rotation window; keep a short expiry and define revocation/session strategy. Do not rely on length alone as proof of entropy. |
| 13 | Server-side API keys | **Partial / configuration review** | Critical | Provider credentials are read from backend settings (`app/config.py:34-46`); `.env.example` uses placeholders. Frontend public env references are API URL, org ID and dev flags, not provider keys. | Keep all provider credentials in server-side secret storage, rotate them, scope them, redact them and validate deployment secret injection. | 17 | Webhook signatures | **Partial — one integration protected** | High | Website intake verifies key ID, timestamp, HMAC-SHA256 with constant-time compare, body size and idempotency in `app/website_intake_routes.py:47-88`; tests are in `tests/test_website_intake.py`. ## Validation evidence recorded

- Backend full suite: **285 passed, 4 skipped**. The four skipped tests require `AGENCY_OS_TEST_DATABASE_URL` and cover PostgreSQL tenant integrity, concurrency and recovery.
- `pip-audit -r requirements.txt`: no known vulnerabilities reported.
- `pip-audit -r requirements-dev.txt`: no known vulnerabilities reported.
- `npm audit`: 0 vulnerabilities after dependency updates.
- Frontend `npm run lint`: **blocked** because ESLint 9 requires an `eslint.config.*` file and none exists.
- Frontend `npm run build`: compilation and type checking passed, but the cloud command ended with exit 130 during static page generation; complete production build is **not verified**.
- No PostgreSQL 16 RLS/migration tests, penetration test, secret-history scan, production deployment review or backup/restore drill was performed.
