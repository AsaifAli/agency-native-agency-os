# 20-Point Pre-Deploy Security Audit — Agency OS

**Audit date:** 2026-11-25
**Scope:** `agency-native-agency-os` current reconciled PR branch, backend, frontend source, migrations, Docker Compose and declared dependencies.
**Disposition:** **NOT APPROVED FOR PRODUCTION**. This is a source/configuration review plus automated dependency and backend-test evidence, not a penetration test, production-environment review or compliance assessment.

## Executive result

- **Verified / not applicable:** 6 controls (SQL injection source review, XSS sink review, no file-upload surface, browser token persistence removed, explicit production source-map setting, dependency audit).
- **Partial:** 11 controls (CSRF applicability, SSRF, BOLA, Redis rate limiting, server-side RBAC, JWT controls, API-key handling, default-credential safeguards, CORS, webhook coverage and logging hygiene).
- **Failed / not implemented:** 3 controls (production password/identity lifecycle, MFA and PostgreSQL RLS).
- **Dependency audit:** npm audit reports 0 vulnerabilities after the frontend dependency patch; pip-audit reports no vulnerabilities in runtime and development requirements after moving pytest to development requirements and upgrading it.

The checklist has 20 rows below; statuses are deliberately conservative. A control marked verified only describes the current code surface, not a guarantee against all attacks.

## Detailed 20 controls

| # | Control | Status | Severity | Evidence / exact finding | Required patch or remaining verification |
|---:|---|---|---|---|---|
| 01 | SQL injection | **Verified (source review)** | Critical | SQLAlchemy ORM queries are used throughout. The only application `text()` call found outside migrations is a fixed literal `SELECT 1` in `app/main.py:108-116` and `app/tool_registry.py:167-178`. AST review found no f-string or concatenated SQL passed to `text()`. | Keep all future SQL parameterized. Add static SQLi scanning to CI and review future raw SQL changes. |
| 02 | XSS | **Verified (source review, limited)** | Critical | No `dangerouslySetInnerHTML`, `.innerHTML`, `document.write` or `eval()` sinks were found in authored frontend `.ts/.tsx` files. React renders user-controlled values through normal escaped JSX. | Preserve escaped rendering. If rich HTML/Markdown is introduced, sanitize with a maintained sanitizer and add browser tests with hostile payloads. |
| 03 | CSRF | **Partial / bearer-only design** | High | API authentication currently uses the `Authorization: Bearer` header in `frontend/lib/api.ts:3-13`; the backend reads the header in `app/auth.py:35-42`. No auth cookie is issued today, so classic ambient-cookie CSRF is not the current primary risk. | Before switching to cookies, implement synchronizer/double-submit CSRF protection, `Secure; HttpOnly; SameSite=Lax/Strict`, Origin checks and tests. Do not solve CSRF by reverting to localStorage. |
| 04 | File upload validation | **Not applicable (no upload surface found)** | High | No FastAPI `UploadFile`/`File()` routes or frontend upload flow were found in authored source. | Keep upload routes absent until needed. | 05 | SSRF prevention | **Partial** | High | User-supplied research URLs are stored as references, not fetched, in `app/domain_routes.py:289-298`. The Claude adapter makes outbound requests to configured `anthropic_api_base_url` in `app/integrations/managed_agents.py:46-61`; `app/config.py` now rejects non-HTTPS, non-`api.anthropic.com`, userinfo-bearing or nonstandard-port provider URLs when Managed Agents is enabled in production. The tool registry validates public HTTPS URL syntax/IP literals in `app/tool_registry.py:42-69`, but does not perform DNS resolution or enforce network egress. | Keep user-supplied URLs non-fetching. Validate provider base URL against a fixed HTTPS host allowlist at startup; block private/loopback/link-local/metadata destinations at egress and after DNS resolution; disable redirects or revalidate every redirect; test DNS rebinding and IPv4/IPv6 cases. |
| 06 | BOLA / IDOR | **Partial — application scoping exists; DB isolation missing** | Critical | Organization membership and workspace checks exist in `app/auth.py:44-49`, `app/domain_routes.py:25-44`, `app/main.py:125-134` and other route modules. | 07 | Rate limiting | **Partial — implementation added, integration verification pending** | High | `app/rate_limit.py` adds Redis-backed per-minute buckets for auth, expensive and general API routes. Existing sender-level hourly/daily caps remain. | Run Redis integration/load tests, configure trusted proxy IP handling at the edge (the app deliberately ignores untrusted `X-Forwarded-For`), and tune limits using real workload data. |
| 08 | Secure password hashing | **Not implemented — no password login found** | Critical | No password field/hash, Argon2id/bcrypt dependency or password authentication endpoint was found. Current user auth accepts bearer JWTs; development token issuance is in `app/main.py:88-105`. | Do not add ad-hoc password storage. Choose an identity provider or implement a complete production auth lifecycle with Argon2id (or bcrypt cost >=12), reset/verification flows, throttling and tests. | 09 | MFA | **Not implemented / external control unverified** | Medium | No TOTP, WebAuthn, MFA challenge or enforcement was found in application code. | Require MFA through the selected identity provider for founder/admin identities and sensitive actions; record verified MFA assurance in the server-side session and test enforcement. |
| 10 | Server-side permissions | **Partial** | Critical | Backend role and explicit Founder Authority checks exist in `app/auth.py:44-53,64-89`; route modules use them. ## Validation evidence recorded

- Backend full suite: **298 passed, 4 skipped**. The four skipped tests require `AGENCY_OS_TEST_DATABASE_URL` and cover PostgreSQL tenant integrity, concurrency and recovery. New tests cover production configuration fail-closed behavior and rate-limit route classification.
- `pip-audit -r requirements.txt`: no known vulnerabilities reported.
- `pip-audit -r requirements-dev.txt`: no known vulnerabilities reported.
- `npm audit`: 0 vulnerabilities after dependency updates.
- Frontend `npm run lint`: completed with **0 errors and 7 existing hook-dependency warnings**; ESLint flat config added.
- Frontend `npm run build`: **passed**, 31 static pages generated. `experimental.cpus=1` avoids cloud process exhaustion.
- `app/rate_limit.py`: Redis-backed auth/expensive/general throttling added; Redis integration/load and trusted-proxy verification remain pending.
- Production config now fails closed for dev auth, mock runtime, weak JWT/database passwords, non-PostgreSQL DB, non-TLS Redis, wildcard/non-HTTPS CORS, disabled rate limiting and untrusted Claude API base URL.
- No PostgreSQL 16 RLS/migration tests, production identity/MFA, penetration test, secret-history scan, production deployment review or backup/restore drill was performed.

## Production release blockers (must close before deploy)

1. Select and integrate the production identity provider/session lifecycle; enforce MFA for founder/admin. The current dev-token path is not production auth.
2. Add PostgreSQL 16 RLS with a non-owner/non-BYPASSRLS runtime role and test tenant context/connection-pool isolation.
3. Run Redis rate-limit integration/load tests and configure trusted proxy handling at the edge.
4. Configure production secret-manager values and verify fail-closed startup in the actual deployment environment.
5. Complete SSRF network egress controls, DNS/IP checks and redirect handling.
6. Complete route-level BOLA/RBAC matrix and PostgreSQL tenant-isolation tests.
7. Finish provider-specific webhook signature verification before enabling those event routes.
8. Centralize PII/secret-safe logging and remove email from CLI logs.
9. Verify deployed artifacts/CDN do not expose `.map` files.
10. Perform independent security review, secret-history scan, deployment config review and recovery testing.

**Release decision: NO-GO.** The dependency vulnerabilities identified during this audit have been remediated in this branch, but the critical identity, RLS and authorization verification gaps remain.
