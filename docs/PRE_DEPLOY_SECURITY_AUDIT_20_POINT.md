# 20-Point Pre-Deploy Security Audit — Agency OS

> **Historical snapshot (2026-11-26):** This audit predates the consolidated PR #71 merge on 2026-11-28. Its point-in-time findings (including workspace-grant and PostgreSQL RLS status) must not be treated as current implementation status. Use `IMPLEMENTATION_STATUS.md`, `POSTGRES_RLS_OPERATIONS.md` and `WORKSPACE_AUTHORIZATION_DESIGN.md` for the merged baseline; the remaining production gates in this audit still require fresh verification.

**Audit date:** 2026-11-26
**Scope:** `agency-native-agency-os` current reconciled PR branch, backend, frontend source, migrations, Docker Compose and declared dependencies.
**Disposition:** **NOT APPROVED FOR PRODUCTION**. This is a source/configuration review plus automated dependency and backend-test evidence, not a penetration test, production-environment review or compliance assessment.

## Executive result

- **Verified / not applicable:** 7 controls (SQL injection source review, XSS sink review, no file-upload surface, cookie CSRF controls, browser token persistence removed, explicit production source-map setting, dependency audit).
- **Partial:** 13 controls, including PostgreSQL RLS implemented on the candidate branch but awaiting live PostgreSQL 16 verification, plus SSRF, BOLA, Redis rate limiting, server-side RBAC, JWT controls, API-key handling, default-credential safeguards, CORS, webhook coverage, logging hygiene, Authentik MFA policy and deployment verification.
- **Failed / not implemented:** 0 controls identified by this source audit; this does not mean production-ready.
- **Dependency audit:** npm audit reports 0 vulnerabilities after the frontend dependency patch; pip-audit reports no vulnerabilities in runtime and development requirements after moving pytest to development requirements and upgrading it.

The checklist has 20 rows below; statuses are deliberately conservative. A control marked verified only describes the current code surface, not a guarantee against all attacks.
