# Claude Managed Agents MCP Gateway

## Status

**Implemented in code and CI-verified on 2026-11-28 (603 backend tests passed; frontend type-check and production build passed). External staging and Anthropic provider/Vault verification remain pending. Not enabled for production.**

The gateway is an optional Streamable HTTP MCP transport mounted by the Agency OS API at:

`/v1/integrations/claude/mcp/sessions/{agency_os_session_id}`

It uses the MCP Python SDK and delegates tool calls to the existing OS Tool Gateway. It does not introduce a second authorization system or write directly to business tables.

## Security contract

- Disabled by default with `CLAUDE_MANAGED_MCP_ENABLED=false`.
- Only tools explicitly listed in `CLAUDE_MANAGED_MCP_ENABLED_TOOL_KEYS` and registered as `read_only` without an approval requirement can be exposed.
- Current read-only registry coverage is intentionally small. The public lead-research capture tool is a write-draft operation and is not eligible for MCP exposure.
- Every HTTP request authenticates a short-lived bearer credential bound to one OS machine identity, one agent session and one workspace.
- Every list/call dispatch revalidates credential revocation/expiry, machine identity, agent session and current workforce capability grants.
- The Tool Gateway rechecks data class, tool scopes, active workforce membership, capability grant, input schema, data protection, idempotency and audit before executing.
- Host and Origin are checked; the MCP SDK's DNS-rebinding protection is configured with the exact public host; request body, concurrency and per-credential request rate are bounded.
- Session credentials are generated by the OS, stored only as hashes in PostgreSQL, and delivered to Anthropic through a dedicated Vault static-bearer credential. They must never be logged or placed in prompts.
- Provider Vault credential IDs are persisted as references, not secret values. Cleanup revokes the OS credential before archiving the provider credential. Ambiguous outcomes require reconciliation/manual review rather than blind credential recreation.
- Before a worker creates a provider credential, PostgreSQL atomically reserves one Vault slot in the same transaction as the OS credential row. A transaction-scoped advisory lock serializes reservations across worker processes. The configured limit defaults to 16 and cannot exceed Anthropic's documented 20-credential Vault limit.
- Credentials with an ambiguous provider-create outcome remain `delete_pending` and continue consuming capacity until reconciled. This is intentionally fail-closed; operators must not manually mark the OS row deleted while a provider credential may still exist.
- No local model, local inference, local fallback, direct database tool access or arbitrary URL dispatch is supported.

## Required configuration

These settings belong in the API and worker runtime environment, not in source control:

| Setting | Requirement |
|---|---|
| `CLAUDE_MANAGED_AGENTS_ENABLED` | `true` |
| `CLAUDE_MANAGED_MCP_ENABLED` | `true` only after the endpoint and Vault are ready |
| `CLAUDE_MANAGED_MCP_PUBLIC_BASE_URL` | Public HTTPS origin only, e.g. `https://agency-os-api.example.com`; no path, query, fragment, credentials or non-standard port |
| `CLAUDE_MANAGED_MCP_VAULT_ID` | Dedicated Anthropic Vault ID beginning with `vlt_` |
| `CLAUDE_MANAGED_MCP_ENABLED_TOOL_KEYS` | Explicit comma-separated list of reviewed read-only OS tool keys |
| `CLAUDE_MANAGED_MCP_REQUESTS_PER_MINUTE` | Per-session-credential request ceiling |
| `CLAUDE_MANAGED_MCP_MAX_ACTIVE_CREDENTIALS` | Active/pending credential reservations in the shared Vault; default 16, hard maximum 20 |
| `CLAUDE_MANAGED_MCP_MAX_CONCURRENT_REQUESTS` | API-process concurrency ceiling |
| `CLAUDE_MANAGED_MCP_MAX_REQUEST_BODY_BYTES` | MCP request body limit |

The API and worker must use the same MCP feature flags, public origin and Vault ID. The API must be reachable from Anthropic over public HTTPS. Route the MCP path to the Agency OS API without rewriting the session UUID path. Use the dedicated `agency_os_app` role for API requests and `agency_os_worker` for worker execution; neither role may bypass RLS.

For Anthropic's restricted environment networking, allow the exact MCP hostname using the environment's host allowlist. Do not disable network restrictions globally merely to make MCP connect.

## Anthropic setup

1. Create or select a dedicated Vault for Agency OS MCP session credentials.
2. Configure the Claude Managed Agent with an MCP server named `agency_os` and the per-session URL supplied by the OS.
3. Add a matching `mcp_toolset`; default tools off and enable only the exact names returned by the OS registry. The toolset configuration names are the bare MCP tool names (currently keys such as `system.health.read`).
4. At session creation, attach the Vault ID. The OS creates a unique static-bearer Vault credential for that session URL; Anthropic injects it on MCP requests.
5. Keep the Managed Agent's other built-in toolsets, skills, MCP servers and multiagent features disabled unless separately reviewed and explicitly supported by the OS policy.

The integration uses Anthropic's Managed Agents MCP pattern: agent configuration declares the remote server and toolset; session creation attaches the Vault. The OS URL is session-specific, so the Vault credential is bound to that exact URL.

## Disable and recover

Set `CLAUDE_MANAGED_MCP_ENABLED=false` in both API and worker runtime environments and restart/redeploy both processes. This stops new MCP session preparation and removes the MCP transport on API startup. Do not delete Vault credentials or database records as a shortcut: use the persisted credential state and cleanup/reconciliation path. If an execution has an ambiguous provider session or Vault state, pause automatic retries and reconcile before creating another credential.
